## 2. 本次代码完成了什么

- **90 秒定时检查**：`PROGRESS_WATCHDOG_SECONDS` 可设 60–120 秒。检查已结算工具记录、文件内容和结果变化；连续没有新证据但仍有活动时，只排队一次诊断，在下一次正常模型请求前交给原 Agent，不额外调用模型、不抢占操作。
- **补齐真实浏览器异常处理**：识别断言读取超时但没有 `passed`／`actual` 的实际回执；删除旧的无界反馈入口。相同失败进入有限诊断，未解决则保留候选并如实收尾，不制造通过。
- **验证**：完整回归 **951/951 通过、0 跳过，330.946 秒**，启用真实浏览器和 Agent Docker 检查。冻结前后 240 文件验证清单一致；真实复测的 237 个提交文件和控制脚本也未改变。

真实 R13 中，F2 产生 2 次排队诊断、1 次安全边界递交。排队提示在条件变化或任务结束后不一定继续递交。没有新增独立诊断模型调用。S1 没有触发巡检提示，却执行了 135 次真实浏览器调用，其中 108 次成功：**有新观察不等于产品有实质进步**。旧的无界拒绝反馈没有在本轮重现，但重复测试问题仍未解决，不能宣布修复成功。

## 3. 主要失败原因与下一步

1. **测试应绑定真实交付版本，并明确何时交接。** S1 在第 4.479 分钟已有候选，却对同一发布源码进行了 135 次开发者浏览器调用，QA 没有实际浏览器调用；S2 的 6 次 QA 浏览器调用全部测试了审核者自己重写的私有脚本，最后语法错误不能归给原字节候选。应记录被测文件与发布清单差异，只对真正新增覆盖继续测试，并给独立 QA 留出执行窗口。
2. **返工必须针对最新版本。** N2 已完成两处要求的修改，审核者也读取新版，却引用旧 artifact 和旧措辞再次返工，触发上限并跳过后续步骤。应在接受返工前核对当前版本、实际差异和未解决证据；增加上限只会延长这类重复。
3. **包装和验收应形成闭环。** F2 的 HTML/CSS/JS/README 已审核且与正式包一致；新增说明及包装任务没有匹配的最终验收，导致全部子任务 done、总体仍 partial。应规划一次针对最终差异的审查并复用有效证据，不能因为已有 ZIP 就自动放行，也不能重复审核未变文件。
4. **把数据可靠性纳入生成产品要求。** 存储读取失败应阻止可能覆盖旧记录的写入；两个标签页提交前应检查最新状态；看板读取失败要显示不可用，不能显示零。普通功能通过并未覆盖这些缺陷。
5. **提高事实审核质量。** 审核者需读取原文和最新产物，区分研究年份、工具版本及适用样本；核对数值所指的指标，避免把长期收益率当短期收益率。F2 应明确不同预测的发表日期，补足估值与产业覆盖。

这些问题同时涉及流程设计、版本证据、模型决策和外部请求。不能仅归结为“模型算力不够”，也没有证据表明扩大时间、Token 或轮数就能解决。90 秒巡检目前是诊断辅助，不能保证识别所有语义上的重复。

## 5. 协议、用量与比较边界

R13 严格按 **S1→S2→N1→N2→F1→F2** 运行，同团队第二题继承第一题上下文，每个场景开始使用新状态与记忆。原题和四角色保留，每题共享 45 分钟墙钟上限，人工等待计入；不设总轮数、调用数或总 Token 上限，单次行动／规划仍限 6,000／3,000 tokens。新闻核查范围先作为明确标注的操作者假设转交，之后收到用户相同口径确认，未倒写成先前已获答复。

本轮 **556 次模型调用、11,069,803 已报告 tokens**；31 次失败请求含 24 次超时、6 次服务 HTTP 错误、1 次输出截断；30 次用量未知，不能记作零。相比 R12，已报告 tokens 减少约 11.9%，调用数基本相同，流程 done 仍为 2，正式包由 2 增至 3，目标产品形式由 5/6 增至 6/6。但部分质量退步，且 R12 跨场景并行、R13 严格顺序，计划、来源可达性及人机等待均不同，不能归因于单项修复或宣称稳定成功率。

本轮同版本重复 review_pass 事件为 0，仍有重复审核行为；事件去重不等于判断不重复。冻结的旧指标脚本遗留 round=12 标签，原输出保留，正式 R13 报告按运行 ID、源码冻结与六份导出更正为 13，没有改动原始结果。所有执行已结算、六份终态唯一导出、全部 ZIP 的 CRC／清单／发布字节 SHA 一致。原始对话、产品和运行数据保留本地，代码仓库只收代码与脱敏报告；专用 8101 测试服务已关闭，用户 8080 服务未切换。

## 6. CrewAI 参考的准确边界

固定源码版本为 `bf6fd3a0972dd72fe1ff568c243e87e3b8408d35`，这里只做静态参考，没有把平台换成 CrewAI。参考的是明确的失败反馈、有限重试和收尾机制，不是把停止循环当成产品通过。

- **执行超时**：`agent/core.py` 第 1066–1083、1090–1128 行选择超时执行并传播超时；同步路径通过线程 `future.result(timeout=...)` 等待后尝试取消。由源码可见，这不能等同于强制终止已经运行的线程或撤销外部副作用。[固定源码](https://github.com/crewAIInc/crewAI/blob/bf6fd3a0972dd72fe1ff568c243e87e3b8408d35/lib/crewai/src/crewai/agent/core.py#L1090)
- **执行错误重试与输出验收重试分开**：前者由 `max_retry_limit` 控制（`agent/core.py` 第 908–934 行）；后者由 `guardrail_max_retries` 控制，失败时把错误和原输出反馈给 Agent，耗尽后报错（`task.py` 第 1425–1510 行）。[固定 guardrail 源码](https://github.com/crewAIInc/crewAI/blob/bf6fd3a0972dd72fe1ff568c243e87e3b8408d35/lib/crewai/src/crewai/task.py#L1425)，[官方 Agent 参数](https://docs.crewai.com/en/concepts/agents)，[官方 Task guardrail](https://docs.crewai.com/en/concepts/tasks)
- **连续相同调用**：固定版本 `utilities/agent_utils.py` 第 1996–2071 行按工具名、参数、输出共同计数，第 4 次警告，第 5 次登记重复失败；错误策略决定是否抛异常，否则执行器导向最终回答。不同调用重置尚未触顶的连续计数；触顶后保持锁定。执行器分支在 `agents/agent_executor.py` 第 2520–2529 行。不能简写成“第五次自动完成任务”。[固定计数源码](https://github.com/crewAIInc/crewAI/blob/bf6fd3a0972dd72fe1ff568c243e87e3b8408d35/lib/crewai/src/crewai/utilities/agent_utils.py#L1996)，[最终回答分支](https://github.com/crewAIInc/crewAI/blob/bf6fd3a0972dd72fe1ff568c243e87e3b8408d35/lib/crewai/src/crewai/agents/agent_executor.py#L2520)

本平台需要额外绑定任务修订、实际源码、审查权限与未知执行状态；这些验证和候选包策略是本项目实现，不应归称为 CrewAI 自带，也不应照搬轮数限制替代用户选择的时间预算。
