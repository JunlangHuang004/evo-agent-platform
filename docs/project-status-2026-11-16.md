# 项目当前能力与作业要求对照（2026-11-16）

本项目已经有可运行的通用多 Agent 后端，能够规划、调用工具、向人提问、传递文件并生成实际产品；目前还不能宣称“六题稳定交付”或“Agent 已通过学习持续提升”。近期工程投入偏向测试、审查和打包收尾，下一阶段需要同时补上作业强调的学习效果、真实委派和完整提交证据。

本报告以 **R12 已结束的六题实测**为能力依据。R13 的定时巡检与循环恢复修复已完成，完整回归 951/951 通过；尚无新的完整六题结果，不能用离线验证覆盖 R12 的失败记录。

## 1. 要求来源与解释边界

依据包括：[Canvas 项目要求](https://canvas.ust.hk/courses/73253/discussion_topics/648693)（本轮重新打开核对，与本地 2026-10-29 快照一致）、`Mid_Test(1)/README.md`、三个场景的角色和六题原文，以及用户后续明确的要求。

- **主项目要求**是通用协作平台：异构 Agent、私聊和群聊、自主拆分与协商委派、人工介入、每个 Agent 的独立记忆与执行文件环境、搜索、文件操作、代码执行测试、Git commit 和 push，并自动统计任务完成与耗时。Canvas 的 **2–4 人指学生组员，不是平台只能有 2–4 个 Agent**。
- **Mid-Test**为每个场景明确指定四个角色；团队应在与人交流中自行确定分工、技术路线、测试方法和完成标准。四角色原文需要保留，但不要求把所有任务都固定成同一条流水线。原文依据：README 第 3、5–9 行，各角色文件第 3 行。
- 文档输出以 Markdown/TXT 为主，不应投入 PDF、Word、PPT 生成能力。F2 明确要求可逐页浏览的 **HTML slides**，这是该题的产品形态；不能把它误解为需要 PowerPoint。主项目也不要求复杂前端设计。
- 用户增加的 45 分钟、会议室具体规则、浏览器本地保存、看板统计口径、校园新闻范围与约 800 词、模拟投资偏好授权仍然有效。它们应标作用户要求，不能混称老师的原题。

## 3. R12 六题实际能做到什么

每题原总预算 45 分钟，不另设总轮数、调用数或 Token 上限；六题均自然到达终态，确认没有未结算执行后唯一导出。没有人为补写产品。结果为 **2 个 `done`、4 个 `partial`，5 题存在所需产品形态，1 题缺主要产品**。这些不是已审定的作业成功率。

| 题目 | 实际产品和流程状态 | 独立检查发现的主要问题 |
| --- | --- | --- |
| S1 会议室预约 | 可下载的浏览器应用；预约、取消、重载及双开冲突的常规路径可用；44.853 分钟，`partial`，候选包 | 存储读取失败被当成空记录，后续预约可能覆盖旧数据；大量重复测试耗尽交接时间，缺当前版本独立验收 |
| S2 用量看板 | 在预约产品上增加真实交互看板；核心统计核对通过；37.432 分钟，`partial`，候选包 | 继承读取失败问题；看板读取失败显示零；取消历史口径不够清晰。内部 QA 测了自己修改的副本，并重复使用错误预期，未形成正式验收 |
| N1 校园 AI 新闻 | 仅两份新简报；10.299 分钟，`partial`，没有文章或社交稿 | 12 次抓取仅 1 次成功，其余为 DNS 失败；资料陈旧，研究停止后下游均未执行，尚余约 35 分钟也没有改计划形成合格报道 |
| N2 AI 写作检测核查 | 完整文章、社交稿、响应式 HTML、说明与候选 ZIP；20.042 分钟，全部子任务结束而总体 `partial` | 新 HTML/文本等发布字节缺独立验收，**不是 ZIP 工具失败**；来源日期、适用范围和反面证据处理不足，社交稿仍有链接占位符。审查者没有实际读取原始来源正文却声称已核查 |
| F1 模拟投资建议 | 配置、风险和介绍等 Markdown 产品及正式 ZIP；27.301 分钟，`done` | 配置总和 100%、金额 HKD 100 万正确；但单只核心基金 45% 违反自设 40% 上限。30%–40% 压力情景已披露，40% 是否符合模拟承受能力仍未确定，并非违反已知用户偏好；包装时变更了一处来源链接 |
| F2 半导体行业研究 | 真实 16 页 HTML slides，桌面按钮、键盘和冷启动深链接可用；26.977 分钟，`done`，正式包与审核五份文件字节一致 | 窄屏溢出/页脚遮挡；来源最新日期写错，同源更新金额未协调；研究覆盖和估值论证仍有限 |

原题规定 S1 可用预约、S2 交互统计、N1 近期校园报道、N2 证据核查、F1 模拟方案，以及 F2 HTML slides；没有统一要求每题 ZIP、固定页数、移动端适配或相同字数。因此 N1 缺报道是直接任务缺口；N2 有文章但缺包装版本验收是内部交付门槛缺口；F2 手机显示问题是额外质量缺陷。S1 数据丢失虽由额外异常测试发现，仍会影响产品可用性。

本轮共 552 次模型调用，服务已报告 12,568,240 Tokens，另有 24 次调用用量未知；不能把未知算零。六份 ZIP 的 CRC 和发布字节 SHA 已核验，但这只能证明包完整，不能证明内容正确。相比 R11，S2 从未完整交付实现进展到真实应用，F1 形成正式包；N1 则从有报道退步为没有报道。不能由单轮结果推导稳定成功率或某项修复的因果收益。

## 4. 测试协议与额外门槛

**存在一项明确协议偏差。** Mid-Test README 第 19 行要求一个场景先 Task 1、再同组 Task 2，之后才进入下一场景。R12 控制器 `run_suite.py` 第 34–37 行同时启动三场景 Task 1，事件记录前三条也显示同一时间启动。每个场景内部的 1→2 顺序和上下文续用正确，但跨场景并行不符合这条原文；下一轮严格基准应改为逐场景执行。平台能并行本身不是功能缺陷。

平台还加入了固定版本独立验收、最终领导汇总、可运行产品的包装契约，以及候选/正式 ZIP 区分。它们是允许自行设计的 Harness 策略，不是老师逐项规定的评分规则。当前规划校验要求四角色都承担实质任务及最终汇总；提示词还引导可运行产品安排包装步骤。应避免这些规则把团队自主设计压缩为僵硬流水线，尤其不要让已有文章因为新增 README 或格式转换就被统计为“完全没完成原题”。

应分别报告：**原题达成、用户额外要求、团队自定标准、内部流程状态、额外健壮性检查**。不得放宽版本或来源证据来制造通过，也不应反过来把所有内部流程门槛说成作业硬要求。

## 5. 下一步按作业价值排序

1. **可靠停表与有限纠错。** R12 新浏览器执行诊断反馈实际触发 0 次；S1 旧分支产生 83 次反馈。真实断言异常形状未被新分类覆盖，旧兜底缺少有限收尾，离线通过没有覆盖这条真实链。R13 已修复该回执识别与旧无界入口，并加入默认 90 秒巡检；951 项回归全部通过，包含真实 Docker 工具和脚本模型的流程测试。历史循环回放在 3 分钟后排队一次诊断，但这不预报真实六题成功。
2. **补足学习与委派的真实实验。** 在相同任务条件下比较有/无已验证记忆；报告命中、实际采用、适用版本和后续效果。另用真实任务验证 Agent 主动向专长角色委派与接回结果，不能用 planner 预先分配替代全部证明。
3. **让失败后能合理继续。** 网页不可达或研究范围过宽时，允许在证据边界内收缩任务、重新分工并明确不确定性；不能无条件放行 partial，也不能因一个研究节点停止就把剩余时间全部浪费。
4. **提高产品和审核质量。** 存储失败必须显示不可用而非空数据；测试应针对实际发布版本；事实检查需读取原始来源、处理日期与相反证据；数值建议需核对自己的约束；最终包装变更应明确纳入审查。
5. **补齐提交材料。** 架构文档应解释路由、记忆、执行隔离；测试报告应给真实完成与耗时、失败模式、记忆变化及协议偏差；准备每位同学半学期持续贡献的 Git 历史截图和第 13 周展示。已有合并/协作代码属于材料基础，不能据此证明每位同学的持续实质贡献，也不能通过最后集中上传补造历史。

## 6. CrewAI 参考的准确边界

固定源码版本为 `bf6fd3a0972dd72fe1ff568c243e87e3b8408d35`，这里只做静态参考，没有把平台换成 CrewAI。参考的是明确的失败反馈、有限重试和收尾机制，不是把停止循环当成产品通过。

- **执行超时**：`agent/core.py` 第 1066–1083、1090–1128 行选择超时执行并传播超时；同步路径通过线程 `future.result(timeout=...)` 等待后尝试取消。由源码可见，这不能等同于强制终止已经运行的线程或撤销外部副作用。[固定源码](https://github.com/crewAIInc/crewAI/blob/bf6fd3a0972dd72fe1ff568c243e87e3b8408d35/lib/crewai/src/crewai/agent/core.py#L1090)
- **执行错误重试与输出验收重试分开**：前者由 `max_retry_limit` 控制（`agent/core.py` 第 908–934 行）；后者由 `guardrail_max_retries` 控制，失败时把错误和原输出反馈给 Agent，耗尽后报错（`task.py` 第 1425–1510 行）。[固定 guardrail 源码](https://github.com/crewAIInc/crewAI/blob/bf6fd3a0972dd72fe1ff568c243e87e3b8408d35/lib/crewai/src/crewai/task.py#L1425)，[官方 Agent 参数](https://docs.crewai.com/en/concepts/agents)，[官方 Task guardrail](https://docs.crewai.com/en/concepts/tasks)
- **连续相同调用**：固定版本 `utilities/agent_utils.py` 第 1996–2071 行按工具名、参数、输出共同计数，第 4 次警告，第 5 次登记重复失败；错误策略决定是否抛异常，否则执行器导向最终回答。不同调用重置尚未触顶的连续计数；触顶后保持锁定。执行器分支在 `agents/agent_executor.py` 第 2520–2529 行。不能简写成“第五次自动完成任务”。[固定计数源码](https://github.com/crewAIInc/crewAI/blob/bf6fd3a0972dd72fe1ff568c243e87e3b8408d35/lib/crewai/src/crewai/utilities/agent_utils.py#L1996)，[最终回答分支](https://github.com/crewAIInc/crewAI/blob/bf6fd3a0972dd72fe1ff568c243e87e3b8408d35/lib/crewai/src/crewai/agents/agent_executor.py#L2520)

本平台需要额外绑定任务修订、实际源码、审查权限与未知执行状态；这些验证和候选包策略是本项目实现，不应归称为 CrewAI 自带，也不应照搬轮数限制替代用户选择的时间预算。
