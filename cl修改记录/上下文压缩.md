# 上下文压缩开发计划

每次模型请求只带三块：角色与工具说明、全队共用的小看板、该成员上一次动作和真实回执。文件正文仍按路径和 SHA256 用 `file.read` 读取。账本里的完整调用记录保留，提示里不再重复粘贴。

## 为什么要改

压缩已经存在：`compress_messages` 和 `adapt_context` 会在发送前裁剪。触发条件是整段提示超过 `MAX_CONTEXT_CHARS`。当前配置是 8 万字符，所以一轮任务里的前许多次请求都是整段私有对话原样再发。

这些重复文本来自三处：

1. 每个成员的 `task['_messages']` 逐轮变长，工具回执里的文件正文和浏览器输出一直留在后续请求里。
2. 子任务开工时，初始用户消息已经包含任务板、依赖结果、群聊原文、产物索引和最近 8 次工具回执。返工或断点恢复时又追加一条「断点恢复/返工上下文」，把其中大部分再贴一遍。
3. 同一份已发布文件的索引，会随每个成员的私有提示各发一份。正文本来就可以按哈希再读，提示里不需要副本。

预算先被这些重复文本用完。发布、独立验收和打包本身用不了那么多 Token。

## 团队共享什么

共享的是服务器从账本重算的一块看板，每轮一份，所有成员读同一份。不共享一份对话记录。

看板只含：

1. 本题目标和运行编号。
2. 子任务：标题、负责人、状态、修订号。
3. 已发布文件：路径、所有者、SHA256。不含正文。要修改必须发布新版本。
4. 未关闭的验收缺口，以及最近一次验收结论。
5. 来源只留网址、标题、调用编号和网页快照路径。抓取正文用 `file.read` 读该快照。
6. 人类已经回答的澄清只在同一请求的 `humanClarifications` 里保留一份原文。看板记录对应的 receipt 编号。

开发者的草稿、失败尝试、私有工作区和本人经验不进这块看板。每个成员自己的上一题成败仍只放进他自己的提示。测试工程师继续只验收已授权的发布字节。

## 每个成员的请求里有什么

1. 系统消息：该成员的身份说明和工具名单。这是稳定前缀，轮次之间不改写。
2. 用户消息：上面的团队看板。由账本重算，替换上一轮的看板，不追加第二份。
3. 紧接着的一条：上一次动作和它的真实回执。更早的文件正文、浏览器输出改为索引：路径、SHA256、调用编号、是否通过。每个路径只保留最新一份正文。

省略的文字标明「未包含正文」。模型要看内容时再 `file.read`。被省略的文本不能当作已经读过，也不能当作测试通过。

群聊原文不放进执行中的请求。上一题交接卡仍只给规划者；执行中的成员看本轮看板。

## 什么时候压缩

工具回执写入账本的同一时刻就压缩该成员之后的工作提示，不等到 8 万字符。

- 同一路径已有更新的正文时，旧正文立刻换成索引。
- 同一浏览器测试已有通过回执时，旧输出换成调用编号和结论。
- 返工只更新看板上的状态、修订号和缺口。不再追加整份「断点恢复/返工上下文」。
- 现有的超限裁剪保留，作为看板和最近回执仍然放不下时的最后一道界限。

完整调用记录、产物字节和事件日志不删。压缩只影响下一次模型请求看见的文本。

## 改哪些地方

| 位置 | 改动 |
| --- | --- |
| `backend/engine.py` 子任务开工 | 初始上下文改为团队看板。群聊原文、重复的最近回执不再塞进每个成员的首条用户消息。 |
| `backend/engine.py` 返工 / 断点恢复 | 更新已有看板。去掉再贴一条「断点恢复/返工上下文」。 |
| `backend/engine.py` 工具回执写入后 | 把该成员更早的同路径正文、同规格浏览器输出换成索引。每个路径只留最新正文。 |
| `backend/runtime.py` `compress_messages` | 继续作为超限时的最后裁剪。索引和最新正文优先于旧对话。 |
| 测试 | 覆盖下面四条，不调用真实模型。 |

## 验收

1. 同一成员连续读取并修改同一文件。第二次模型请求仍含最新正文，第一次的正文只剩路径、SHA256 和调用编号。
2. 开发者已经发布页面。测试工程师的请求含该文件的哈希，不含开发者的私有对话和失败尝试。
3. 子任务返工后，工作提示里只有一份看板。不再出现第二条完整的「断点恢复/返工上下文」。
4. 看板超过现有上限时，现有裁剪仍会拦住请求。被省略的正文不会被写成「已读」或「测试通过」。
