## 11 月 23 日 00:25 提交

- 长任务改为更小的计划：实现、测试和返工不要预先拆成重复子任务；研究交接只要求一份简明证据简报。
- 同一运行里已经抓到的公开网页快照，队友可以用 `file.read` 再读，不必因为别人抓过就重新 `web.fetch`。
- 工作上下文会压缩：旧的文件、浏览器和网页正文收成路径与哈希索引，最新正文保留，账本本身不删。
- 上一题结束后生成交接卡片，下一题的策划能看到已发布文件和沿用规则。卡片是事实，不是新题目的指令。
- `reviewOf` 只绑定要审查的生产者任务。审查任务不再因为负责人没有 review 能力就直接失败。
- 动作 JSON 连续两次自动格式修复仍失败时，不再立刻判失败，改为询问是否再修一次。审核重复恢复和浏览器诊断收尾仍然直接失败，不走这次人工修复。
- 考试团队增加独立的「版本 / 发布」profile：实现负责代码和网页，发布负责 Git 与交付，两者不再共用同一套工具。
- 每个 Agent 可以勾选多个能力 profile，工具和调度能力取并集，至少保留一个。自建团队也可以选 profile 并注入角色提示词。
- 七种能力 profile，以及所有 Agent 的动作提示，都写入同一句共享要求：高效完成，不要重复已经成功或已经记录的读取、发布和审查；要求已满足时直接交卷。
- 开发者对同一已发布字节、同一浏览器检查再测时，直接引用上一次通过回执，不再启动容器。QA 的独立测试不走这条短路。
- Claude 会话里的记忆改动：任务成功时按稳定签名自动写入候选策略，不再只靠模型自己写 reflection。同一签名累计两次独立成功后，用 `result:<run>:<task>` 回执自动确认。下一次规划时，策划从已验证层读取最多 3 条相关经验，放进 `priorExperience`。确认前仍不是共享策略，工具权限和各 Agent 的记忆隔离不变。
- `file.read` 可以按函数名查找或按行窗口读取，避免反复整文件重读。
